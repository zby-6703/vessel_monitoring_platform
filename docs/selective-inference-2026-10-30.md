# 2026-10-30 选择性识别与自适应变焦验收

实时链路在船舶/区域检测、跟踪之后筛选目标，仅对符合条件的目标运行船名与吃水模型。小目标继续检测和计数，不触发新录像、不写入完整识别档案；轻量轨迹可在后续满足条件时升级，不更换原有轨迹身份。

## 默认策略

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| 最小船高 / 船宽 | 参考画面 6% / 12% | 入选条件，与变焦目标高度不同 |
| 连续观测 | 3 次且至少 0.4 秒 | 排除瞬时框，漏检或观测间隔过长重新确认 |
| 识别间隔 / 单帧预算 | 每目标 0.8 秒 / 最多 1 个 | 大目标优先并照顾等待较久的目标 |
| 监测区域 | 全景 0–100% | 可配置固定机位下的航道范围，按船框中心判断 |
| 尺寸退出阈值 | 入选尺寸的 80% | 减少边界抖动导致反复分流 |

船头从左右边缘进入时暂不使用最小宽度限制；高度和稳定性仍需达标。摄像头按已测量的光学倍率归一化到 1×；镜头运动、倍率未知、关联歧义时暂停详细模型。已锁定录像目标仍保留检测关联，不会因识别预算、尺寸波动而误判离场。

自适应倍率增加早期高度波动抑制、裁切观测下界保护及 3% 竖直边缘余量。停泊判断继续要求可靠背景运动补偿；不能确认背景运动时不累计为停泊证据，也不能仅凭大船条件触发自动光学录像。

## 真实片段对比

环境为本机 RTX 5060 Ti、Conda Train、当前部署的 RT-DETRv4-S、船名 OCR 与 V120 模型，使用 `assets/20251211082541.mp4`。视频 2560×1440，共 644 帧，约 26.27 秒；均匀采样 120 帧，两次流式解码所得每个采样帧 SHA256 一致。两条路线都包含真实 TrackTrack 跟踪；选择性路线另包含背景运动估计和筛选。计时排除解码、数据库、JPEG 推送、视频编码和模型加载。

| 项目 | 每船完整识别 | 选择性识别 |
| --- | ---: | ---: |
| 检测模型调用 | 120 | 120 |
| 船名 OCR 调用 | 23 | 2 |
| 吃水模型调用 | 62 | 12 |
| 检出船框观测总数 | 820 | 820 |
| 平均处理时间 | 83.34 ms/采样帧 | 61.52 ms/采样帧 |
| 对应处理吞吐量 | 12.00 FPS | 16.26 FPS |

本次船名调用减少 91.3%、吃水模型调用减少 80.6%，总处理时间减少 26.19%。选择性路线有 567 次符合条件的观测、253 次轻量观测，117 次详细处理调度；调度目标当帧没有船名或吃水区域时，不调用对应下游模型。采样包含稳定性确认、低置信度、尺寸不足、关联歧义、预算及冷却等分流，没有发生停泊排除。模型及解码错误均为零。

原视频画面有历史 OSD `Z:3`，此处将**录制画面作为参考视野**；该结果不等于摄像头物理 1× 的尺寸阈值验收，也不能据此断言各船真实船型或大小。两帧完整路线预热不保证两个下游模型都已遇到对应区域；先后运行顺序、GPU 状态亦会影响单次测速。因此这些数字用于确认下游调用减少，不保证现场全链路 FPS。没有船型、船名、吃水或停泊真值标注，此次不宣称准确率提升，也未进行新一轮实机镜头运动测试。

脚本：`scripts/benchmark-target-filter.py`，默认不访问真实摄像头、不改生产数据库和录像目录。运行示例：

## 现场使用

自动化验证：Train 环境后端 236 项测试通过，前端类型检查与生产构建通过。摄像头推理循环集成测试实际使用检测服务、TrackTrack、属性聚合和临时 SQLite：8 帧检测中，小目标不调用船名/吃水模型，大目标调用各 2 次；保留 2 条计数轨迹，仅生成 1 条完整识别档案。另覆盖光学倍率未知、镜头运动、裁切、已锁定目标、ROI 校验、预算公平性及旧配置兼容。

刷新实时监测页，在“目标筛选与循环录制”中调整入选最小船高、稳定性和监测区域，然后保存；不需要开启录像才能应用筛选。开启光学循环前检查镜头能力，确认镜头处在已标定档位。以现场 1× 全景中的近船、远船、小艇、停泊船及多船遮挡样例校准尺寸和航道区域，再验证从船头进入至船尾离场的单轮录像。

大小阈值只是一种图像尺度策略，不能消除检测器的误检、重复框或遮挡。画面方向变化后需重新检查区域；外部客户端改变镜头后需重新检查能力或重新启动采集。关闭重点筛选可恢复所有检测目标的原完整识别流程。

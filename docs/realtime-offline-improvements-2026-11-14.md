# 2026-11-14 实时监测与通行录像离线补全

## 功能与操作

1. 实时监测的“船名识别”和“吃水测量”分别保存为 `enable_ship_name`、`enable_draft`。保存后在下一帧生效，关闭时不调用对应模型并释放实时会话所持模型。启动实时会话只加载检测模型，详细模型在出现相应区域且功能开启时按需加载。两项关闭仍保持筛选资格，合格目标可以触发录像，不会因为跳过识别而被排除。
2. 系统状态新增主辅流频道读取及选择。查询和选择均使用设备实际 ONVIF Profile，不拼接猜测的 RTSP 路径。持久化匹配的媒体、视频源及 PTZ 配置 Token 与帧率；选择后取消旧播放转发地址，使用所选服务器采集源预览。采集/回放/光学动作/对焦未退出时拒绝切换。摄像头地址或凭据在部署配置中改变后，旧覆盖不再适用。另一物理视频源需要重新配置标定，不沿用当前镜头标定。
3. 增加有界云台方向操作、保存/恢复监测机位、手动框选/坐标区域对焦和可选自动区域对焦。方向命令采用设备声明的速度空间，操作后发送 Stop；监测机位仅保存在本机，不覆盖摄像头已有预置位。恢复机位检查镜头 1× 和实际云台位置。区域对焦依据新采集图像的局部 Laplacian 清晰度，围绕当前真实焦点进行两轮小范围搜索，最多比较四个新位置，并回到观测最佳位置；缺少绝对位置/IDLE 反馈时不宣称到位。对焦不占用视频采集或模型推理线程；光学录像在对焦期间继续写入原始画面，并忽略失焦帧的离场证据。对焦结果写入该轮录像的 `focus_events`。
4. 每段可播放的已归档或中断录像可创建完整离线作业，固定开启跟踪、完整流水线，不受实时识别开关影响。输入使用硬链接或流式文件复制，避免将整段视频读入内存；保留通行开始时间作为离线时间轴原点。作业和录像双向关联，重复点击复用进行中的作业，完成后回写船名、吃水、轨迹及状态，支持失败/取消重试和上次成功结果保留。启动后对未完成/丢失的作业关系进行失败恢复，避免录像永久锁定。
5. 推理调度按帧串行，已等待的实时帧优先，离线任务在帧边界让出资源。当前帧的单次 ONNX 调用不能被中途抢占；实时和离线各自的模型仍可能同时占用显存，低显存设备应错峰执行完整离线任务。

## 验证与使用边界

后端在 Conda `Train` 环境执行全量回归，**366 项测试通过**；前端通过 `vue-tsc` 和 Vite 生产构建。新增测试覆盖功能开关组合、关闭识别仍触发真实视频、可选模型缺失时检测启动、频道持久化/凭据变更失效/活动源互斥、离线幂等/回写/重试/取消/重启、局部清晰度与焦点搜索边界、失败恢复、云台停止以及实时推理优先级。

区域对焦和云台动作已通过受控设备响应验证，并只读核实现场设备能力；尚需在河边用移动实船验收清晰度、对焦收敛、镜头方向和完整通行覆盖。自动区域对焦默认关闭，按现场效果启用。当前光学循环采用固定监测机位，方向操作用于调整取景机位；单个镜头不能同时提供互不影响的全景和跟随机位，跨电脑需要协调镜头控制端。区域清晰度也会受运动模糊、水纹、压缩与光照影响，不能将指标提高等同于船名/刻度一定可读。

## 协议依据

- [ONVIF Imaging Service 5.3.1–5.3.2](https://www.onvif.org/specs/srv/img/ONVIF-Imaging-Service-Spec.pdf)：先读取 GetMoveOptions，使用设备所支持的焦点 Move 和实际位置反馈；焦点 Move 会退出自动对焦。
- [ONVIF PTZ Service](https://www.onvif.org/specs/srv/ptz/ONVIF-PTZ-Service-Spec-v1712.pdf)：按配置空间使用 ContinuousMove、AbsoluteMove、Stop 和 GetStatus。
- [ONVIF Media Service](https://www.onvif.org/specs/srv/media/ONVIF-Media-Service-Spec-v1706.pdf)：使用 Profile 和 GetStreamUri 选择已有码流。

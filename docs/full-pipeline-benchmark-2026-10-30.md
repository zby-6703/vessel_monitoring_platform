# 2026-10-30 全流程速度实测

本机 RTX 5060 Ti、Conda Train、CUDA FP32、B=1、TF32 关闭，使用当前 RT-DETRv4-S、船名 OCR、V120 字符/水体模型及结构约束吃水算法。

**单船、船名与吃水区域均存在时，预热后的完整推理平均 74.20 ms/帧，约 13.48 FPS。4K 视频通过实际平台 API 处理，不导出标注视频约 10.02 FPS，导出标注视频约 5.36 FPS。**

## 计时口径

| 范围 | 平均折算耗时 | 处理吞吐量 |
| --- | --- | --- |
| 内存图像完整推理：船舶/区域检测、裁剪、船名 OCR、字符检测、水体分割、后处理与吃水计算 | 74.20 ms/帧 | 13.48 FPS |
| 实际 4K 视频任务：解码、上述推理、跟踪/聚合、JSONL/CSV、数据库写入；不导出标注视频 | 99.84 ms/处理帧 | 10.02 FPS |
| 同一 4K 视频任务，再加标注绘制、视频写入和最终 H.264 转码 | 186.54 ms/处理帧 | 5.36 FPS |

第一行不包含文件解码、绘图、落盘或视频编码；后两行是整个服务端任务完成时间，包含任务收尾，不能当作逐帧推理延迟。三种口径均不含首次加载模型、上传和排队等待。当前三模型单独加载耗时约 1.78 秒，首帧还可能需要额外 CUDA 初始化。

## 完整推理分解

使用 `assets/pl_732.jpg`（2560×1440）及 `assets/pl_813.jpg`（4608×2592），两张均检出一条船、一个船名区域和一个吃水区域。每张预热 3 次后测量 20 次，总计 40 次；以外部单调时钟计整个 `FrameInferenceService.infer` 调用，检查没有模型调用错误。

| 环节 | 平均耗时 |
| --- | --- |
| 船舶与区域检测，含预处理/输出恢复 | 28.79 ms |
| 船名裁剪与 OCR | 17.85 ms |
| 吃水裁剪、字符/水体推理、掩码恢复、水体轮廓及吃水规则 | 27.41 ms |
| 其余组装与结果校验 | 约 0.15 ms |
| 完整推理合计 | 74.20 ms |

完整推理 P50 为 74.29 ms，P95 为 78.67 ms。两张分别平均 72.53 ms 与 75.87 ms。另测的两张未检出船名区域，因此未执行 OCR，约 55.61～58.02 ms；这些样本不纳入完整三模型的 13.48 FPS 结论。

## 实际视频任务

从 `VID_20250416_105930_01m00s-02m20s.mp4` 起始处无重编码截取短片，保留 3840×2160、约 30 FPS 原始帧；每次逐帧处理 60 帧（约两秒视频），`frame_step=1`、`enable_tracking=true`、`task=full_pipeline`。通过运行中的 `/api/jobs` 上传并等待完成；预热服务模型后，分别以 `visualize=false` 和 `true` 各运行 3 次。

| 输出标注视频 | 三次任务耗时 | 合计处理帧数 | 按总帧数/总耗时计算 |
| --- | --- | --- | --- |
| 否 | 5.985、6.019、5.968 秒 | 180 | 10.02 FPS |
| 是 | 11.564、11.044、10.970 秒 | 180 | 5.36 FPS |

所有任务完成，360 个处理帧均为一条船，均有船名和吃水区域，帧级模型错误为 0。平台内部 `processing_ms` 约 72～75 ms/帧，与独立完整推理测速一致；额外任务时间主要来自解码、结果处理及可视化视频导出。此处 FPS 指处理吞吐量，不能视为导出视频的播放帧率。

这是本机单船、短视频、无其他排队任务的测量。多船会增加 OCR/吃水区域调用次数；长视频、CPU 负载、分辨率、磁盘和编码配置变化均会影响速度。目前这组配置不能保证对 30 FPS 视频每帧实时完成全流程。

原始逐次数据和六个任务 ID 保存在本机 `data/model_validation/2026-10-30/full_pipeline_benchmark.json`，可重现脚本为同目录 `benchmark_full.py`；测试视频、结果与日志按项目约定不提交 Git。模型身份与基础验收见 [部署记录](model-deployment-2026-10-30.md)。

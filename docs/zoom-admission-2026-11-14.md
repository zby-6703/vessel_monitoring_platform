# 放大门槛调整与现场恢复

## 现场证据

用户反馈开启水平跟随后一直不放大。读取最近通行视频记录与运行状态，发现以下问题：

- 入画要求同时满足 3% 边缘余量、至少三次观测、宽度变化不超过 10% 且稳定 1 秒；每次水平居中又清空稳定计时，容易错过放大时机。
- 自适应最小倍率 3× 被当作硬下限。部分船在画面下方，2× 能容纳完整竖直船体，3× 不能，旧规则直接选 1×。
- 等待入画后得到 1× 计划时进入了“已放大”阶段，失去随船体位置改善重新尝试入画放大的机会。
- 本机镜头每次水平移动后有少量俯仰位置反馈差异。用初始俯仰累计比较，将多次已确认的小差异误判为外部上下移动，最终暂停循环。
- 水平跟随后的参考坐标可能超出原始 [0, 1] 横向范围；监测区判断没有减去跟随偏移，误判仍在当前画面里的船已经超出监测区。

## 新策略

| 条件 | 新行为 |
| --- | --- |
| 主体完整入画 | 默认左右留 1% 余量，两次新观测、短暂确认 0.4 秒即可；允许正常检测框宽度抖动 |
| 等待较久但一端仍截断 | 默认等待 3 秒，至少两次有效船体观测，当前可见宽度不少于画面 35%、中心位于画面 20%–80%，且并非两端都截断时，可尝试不超过 2× |
| 仅窄船头入画或两端均截断 | 继续 1× 录像，不因等待时间到期直接放大 |
| 优先最低倍率无法取景 | 可以使用较低的已标定档位，例如 2×；最大倍率和竖直取景边界继续生效 |
| 当前位置已有可用放大档位 | 先进入该档位，后续继续水平跟随，避免反复居中阻止放大 |
| 只有 1× 能取景 | 保持等待阶段，后续新观测可以重新触发放大；界面显示等待原因 |
| 水平反馈 | 对比上一已确认位置检测外部上下突变，并核验每次动作的垂直变化；不会主动发送上下调整 |
| 监测区 | 使用随水平镜头移动的局部 1× 坐标；身份和尺寸仍保留在参考坐标系 |

入画等待开关继续生效，等待上限可在高级参数调整。放大后最短观察、目标关联和离场确认仍使用现场已保存值；本次不覆盖用户另行调整过的这些参数。录像清单额外保存 `body_entry_reason`，区分完整入画与等待后的温和放大。

## 验证

从最近三段真实通行视频分别取 1、1.5、2、2.5、3、4 秒的画面，使用本机实际船舶检测模型重新推理，共 18 个样本。新规则在其中一段的 5 个连续样本满足入画并选择 2×；这 5 个样本均被旧 3× 硬下限挡在 1×。另外两段抽样因取景位置或主体入画限制继续保留全景，未删除竖直取景保护。

该检查是只读录像/模型回放，不会驱动摄像头，也不是新一艘自然过船的实机全过程验收。原始视频保留不变，本机回放报告位于被忽略的 `data/zoom-admission-2026-11-14/replay-report.json`。

在生产采集停止后，对真实镜头执行 1× → 2× → 1×，各档位均获得停止及实际倍率反馈，水平机位前后一致；本机报告位于 `data/zoom-admission-2026-11-14/hardware-zoom-report.json`。放宽后的 1% 余量、0.4 秒确认、3 秒温和放大等待已通过配置 API 保存，随后恢复现场采集，水平跟随仍开启。

Conda `Train` 环境全量后端测试 408 项通过，前端类型检查及生产构建通过。回归覆盖低倍率回退、框宽抖动、两次观测确认、跟随后保留等待进度、1× 计划重试、窄船头与双端截断保护、俯仰反馈小漂移与真实突变、跟随后的监测区判断。

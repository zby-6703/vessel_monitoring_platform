# 2026-11-12 过船录像完整性修复

本次修复程序的选档、身份关联和媒体保存逻辑，未改远程网络、设备编码、摄像头方向、焦点或本机已保存的固定 4× 策略。倍率实际执行时新增安全限制。

## 修复内容

1. **固定倍率同样检查竖直安全视野。** 原固定模式直接返回请求倍率，跳过自适应模式已有的视野检查；目标接近画面上下边缘时，可能放大后整艘船都不在画面内。现在请求倍率作为上限，降低时只使用已有标定档位，必要时使用 1×；本轮中目标靠近边界时，也允许在冷却条件下受控降低倍率。记录请求值和实际档位，界面说明这一行为。
2. **灰度目标允许保守的几何重关联。** 原实现重新绑定 selector ID 需要颜色直方图，而灰度/红外船体通常没有颜色特征。现在将旧船框裁到当前光学视野后，在共同的 1× 参考平面比较船高和重叠程度；无可靠颜色特征时要求候选唯一、连续至少 3 次且跨度至少 0.3 秒。多船重叠不强行换绑，明确冲突的颜色不能走这个回退路径。已有 selector ID 也不能掩盖重叠灰度船的歧义。
3. **不再丢弃重识别等待期间的实际视频。** 初次确认目标前直接写入真实源帧，避免 JPEG 待确认缓存到上限后丢失早期画面。正常网络条件下，重识别超时保存到超时点，不再回切到最初的目标证据附近；确认离场的正常片段仍及时停止写入，不无限附加空画面。
4. **在同一视频中回到全景恢复一次。** 放大视野中等待超时或持续身份歧义后，保持同一文件打开，回到已确认的 1× 再给一次有上限的确认窗口；本轮不再放大。若成功关联，继续同一段录像到目标离场；如果全景仍超时，则保留视频并明确标记中断。最大单轮时长仍生效。
5. **补齐光学模式预录。** 原光学路径没有实际使用保存的预录秒数；现在从本轮稳定全景缓冲中保留有限的触发前画面，避免确认目标后才出现录像开头。每轮使用独立缓冲，不沿用上轮变焦视野。
6. **归档状态如实反映结果。** `target_not_reacquired`、`target_ambiguous` 和 `target_evidence_timeout` 不再当作正常完成；界面显示关联恢复的全景保底，并移除“目标证据不足等于实物船已离场”和“下载即完整过船”的误导性提示。历史文件没有重写。

## 验证

- Conda `Train` 下后端全量 **318 项测试通过**，前端类型检查及生产构建通过。
- 新增回归覆盖：固定倍率竖直安全档位、真实失败样本的目标位置、灰度 ID 失效后重关联、多船歧义、水平裁切后的同船关联、冲突船体颜色拒绝、同文件全景恢复、预录，以及超时视频逐帧解码。
- 真实 MP4 回归检查后续画面像素确实保留，避免只靠重复触发帧补足时长来通过测试。网络异常、旧视野结果、停止采集、最大时长和归位失败等原有用例继续通过。
- 用当天 23 段真实录像清单的目标位置与原策略重新计算选档，新规则降低了其中 12 次不安全的固定倍率。此验证仅说明规划逻辑得到修正，不等于重新拍摄了那 23 次过船。报告保存在本机 `data/camera-setup/zoom-policy-replay-2026-11-12.json`。
- 服务使用 `Train` 重启，恢复每 3 帧采样的远程摄像头采集；浏览器显示真实画面、模型就绪、自动录制已开启、新的固定倍率安全提示。采集恢复后的独立 API 核验保存在本机 `data/camera-setup/recording-fix-verification-2026-11-12.json`。

## 限制

重关联是基于视觉证据的保守判断，不保证灰度同型船、严重遮挡或远程传输异常下身份始终可辨。没有修改底层远程传输方案或声称消除了丢帧、断流。网络异常期间的有限镜头恢复与媒体收尾沿用原有边界。

重启后尚未取得一段新的自然过船完整录像作为现场验收；本次验证由真实目标位置回放、受控状态机/编码测试及实机监控恢复共同组成。旧短片中此前已经丢弃的画面无法补回。
